# ShoesStoreApp

Настольное приложение магазина обуви для Windows. Покупатель просматривает каталог, добавляет товары в корзину и оформляет заказ с выбором пункта выдачи. Менеджер просматривает каталог и заказы; администратор также добавляет, редактирует и удаляет товары.

## Стек

- C# и .NET 9, WPF, MVVM
- Supabase Auth, PostgREST, Storage и PostgreSQL
- Пакеты `Supabase`, `Supabase.Gotrue`, `Supabase.Postgrest`

## Устройство проекта

`Views` содержит окна и страницы, `ViewModels` управляет их состоянием и командами, `Models` описывает записи базы. `Services/AuthService.cs` отвечает за вход и регистрацию. `Services/SupabaseStoreRepository.cs` реализует `IStoreRepository` для товаров, заказов, пунктов выдачи, ролей и загрузки изображений. `StoreValidation` содержит проверки форм и заказа. `supabase/migrations` содержит политику доступа базы.

Роли хранятся в `public.profiles` и читаются после входа. Отображение кнопок по роли лишь удобство интерфейса: операции защищены RLS в Supabase. Регистрация всегда создаёт роль `client`; администратора и менеджера назначает владелец базы.

## Возможности

- Каталог с ценой и скидкой, поиск по названию и сортировка по цене для сотрудников.
- Регистрация, вход и гостевой просмотр каталога.
- Корзина, расчёт суммы и оформление заказа с пунктом выдачи.
- Просмотр заказов сотрудниками, управление товарами администратором и загрузка изображения товара.
- Проверка адреса почты, пароля, полей товара и условий оформления заказа; сообщения об ошибках загрузки и сохранения.

## Запуск

1. Установите .NET 9 SDK на Windows.
2. Создайте проект Supabase с таблицами `products`, `pickup_points`, `orders` и публичным Storage bucket `images`, соответствующими моделям из `Models`. При использовании существующей базы сначала проверьте соответствие полей, типов и ограничений моделям.
3. Проверьте и примените [SQL-миграцию](supabase/migrations/20261006_security.sql) через SQL Editor в Supabase. В миграции создаётся `profiles`, включается RLS для таблиц и ограничивается запись в `images`. Старые роли из `user_metadata` не переносятся автоматически. Назначьте их вручную из доверенного сеанса SQL, например: `update public.profiles set role = 'admin' where id = '<uuid пользователя>';`. Не добавляйте в приложение `service_role` key.
4. Установите переменные окружения в терминале, из которого запускаете приложение:

   ```powershell
   $env:SHOES_SUPABASE_URL = 'https://<project>.supabase.co'
   $env:SHOES_SUPABASE_ANON_KEY = '<publishable/anon key>'
   dotnet run --project ShoesStoreApp.csproj
   ```

   URL и ключ не хранятся в исходниках. Anon key является публичным ключом клиента; безопасность операций обеспечивают RLS-политики. После переноса конфигурации из исходников рекомендуется перевыпустить старый ключ в панели Supabase, если это позволяет ваш проект.

5. Зарегистрируйте пользователя или откройте каталог как гость. Если в Supabase включено подтверждение почты, подтвердите адрес перед входом.

## Проверка

`dotnet build ShoesStoreApp.sln` собирает приложение. `dotnet run --project Tests/ShoesStoreApp.Tests.csproj` выполняет автономные проверки бизнес-логики без подключения к Supabase. Для проверки RLS примените миграцию в тестовом проекте и убедитесь, что гость читает только каталог/пункты выдачи, клиент видит только свои заказы, менеджер видит все заказы, а изменять товары и изображения может только администратор. Живую базу приложение не перенастраивает самостоятельно.

## Ограничения

Для работы с реальными данными нужны собственный проект Supabase, таблицы и применённая SQL-миграция. SQL в репозитории подготовлен по текущим моделям, но требует проверки на существующей схеме перед применением. Скриншоты в README не добавлены.
